# 澄清阶段裸数字回答未被采纳

任务日期 2026-11-26。状态已修复。

## 原因

上一轮问「你计划玩几天？」时，用户只回一个数字（如「1」「三天」），系统没有把它当作天数：

- 规则解析 `_explicit` 只识别「N 天 / N 日游」形式，裸数字返回空；
- 模型解析对单字「1」也返回空 changes；
- 于是 `missing` 里始终缺 `days`，对话反复追问同一句，用户卡死。

## 范围与边界

- 修改 `app/graph/nodes/clarify.py` 的 `_explicit`：当上一问是 `days` 且整句就是一个数字（可带「天」与句末标点）时，解析为天数。
- 不改对话状态机、不改提示词、不改前端。
- 预算类的裸数字已有独立分支（仅在问预算或出现「元」时生效），本次不合并两者的判定，避免把「1」误判成预算。

## 验收

1. 问「玩几天」→ 用户回「1」→ `days = 1`，对话进入 ready。
2. 回「三天」→ `days = 3`。
3. 回「3天」「玩3天」→ 行为不变。
4. 问预算时回「1」仍按预算处理，不写入天数。

## 验证记录

- `_explicit("1", "days") == {"days": 1}`，`_explicit("三天", "days") == {"days": 3}`。
- 两轮对话走通：轮 1 `ask / missing=['days']`，轮 2 `ready / missing=[]`，`travel_request = {destination: 北京, days: 1, budget_total: 0.0, pace: moderate}`。
