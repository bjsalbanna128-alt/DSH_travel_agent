# 规划草稿、AI 调整与确认

## 原因与目标

规划生成后便写为已完成，确认和调整按钮没有完成对应业务操作。DSH 也由游客确认。网页和 DSH 先生成可打开的待确认草稿，游客在同一详情页查看、调整和确认。

## 范围和边界

- SSE 和 WebSocket 在 LangGraph 到达人工确认点时停止生成并保存草稿，返回真实 `trip_id`。MCP 返回草稿链接和待确认状态。
- 复用行程的 `draft`、`completed` 状态及版本表。决策以数据库中的草稿和版本为准，原进程的内存检查点失效后，仍可以从详情页提交决策。旧完成行程继续可读。
- 详情页统一提供确认和文字调整。调整依据当前草稿，仅合并模型返回的指定日期改动，保留其余日期，并更新受影响路线和费用估算。涉及目的地、天数或需要完整重排的请求提示新建规划。
- 确认需要登录草稿所属账号。DSH 当前以 MCP 配置凭证调用，因此游客须用与草稿归属一致的账号打开链接。DSH 的逐用户凭证转发须由联调环境提供。订单、价格核库和支付不在本次范围。

## 验收与回归

1. 网页 SSE、WebSocket 和 MCP 返回同一种可读的待确认草稿。进入或刷新详情后可识别草稿状态，等待期间没有已确认的提示。
2. 反馈「第三天删掉杜甫草堂」生成同一行程 ID 的新版本，保留未指定的日期。调整失败时草稿和旧版本保留。
3. 确认当前版本后历史和详情显示已确认。重复确认同版本可安全重试，旧版本决策返回冲突，其他账号访问返回 404。草稿不能绕过决策接口用手动编辑或回滚变更。
4. 回归测试使用隔离数据库、真实图中断与受控模型响应，覆盖草稿保存、调整、确认、冲突和账号权限。运行前端构建及浏览器操作，验证 MCP 解析 SSE 草稿事件。

## 验证记录

- 后端 pytest 通过 19 项。测试使用真实 LangGraph 中断和隔离 SQLite，覆盖 SSE 与 WebSocket 草稿保存、同一行程调整后的版本更新、账号隔离、旧版本冲突、重复确认，以及内存检查点不可用时从数据库继续审阅。模型返回空调整或超出明确指定日期时，测试确认原草稿保留。
- 前端用 `npm run build` 构建通过。以临时账号在浏览器生成草稿，打开详情，在第三天删除杜甫草堂，看到版本从 1 更新到 2、估算从 100 元更新到 40 元，再确认并从历史行程看到已确认状态。初始路书和 AI 响应均使用测试替身。
- MCP HTTP 适配模拟通过。工具从 `approval_required` 取出已保存的草稿 ID，回查后输出待确认链接。旧 `done` 事件无法冒充草稿事件。真实 DSH 端到端和 DeepSeek、地图联调待验证。
