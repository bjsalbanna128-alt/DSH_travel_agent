# 业务接口强制登录

## 原因与目标

已有注册和 JWT 登录功能，部分接口仍以匿名身份调用，行程详情、编辑和版本接口也缺少归属校验。游客须登录后使用旅游服务。系统以鉴权结果识别调用者，并限制行程和规划会话访问范围。

## 范围和边界

- 登录、注册和 `/health` 继续公开。澄清、SSE 规划及恢复、行程查询和编辑、版本和回滚、个人画像使用 FastAPI 鉴权依赖。
- HTTP 沿用 Bearer JWT。检查凭证有效期和账号是否存在，业务层从鉴权结果取得用户 ID。
- 行程操作按归属查询。规划检查点按用户隔离。行程落库时检查既有记录归属，避免相同会话号修改另一账号的数据。
- 网页拦截未登录的业务页面。WebSocket 通过首条消息提交 JWT，验证成功才处理业务消息。MCP 使用现有 `TRAVEL_API_TOKEN`。
- 旧匿名行程暂留库中。数据迁移、审批流程修复、角色权限和登录协议改造另行立项。

## 验收和影响

1. 业务 HTTP 接口对缺少、失效、过期或找不到对应账号的凭证返回 `401`。登录、注册和健康检查可匿名调用。
2. 有效用户可澄清需求、提交规划、查看和操作自己的行程及画像。请求里的 `user_id` 不参与确定身份。
3. 其他账号的行程详情、版本、编辑和回滚返回 `404`。其他账号的规划会话无法恢复或覆盖。
4. 游客打开业务页面会进入登录页。过期凭证被 HTTP 或 WebSocket 拒绝后，网页清理登录状态。WebSocket 完成鉴权后可继续聊天。
5. MCP 缺少或使用失效凭证时，工具返回明确提示。有效凭证沿用原有规划和查询接口。

影响范围包括原有匿名网页访问、匿名 MCP 调用、已有行程链接、规划内存状态及登录退出时的前端状态。回归检查覆盖公开入口、旧有本人行程、浏览器和工具的登录路径。

## 配套测试

- 在 `backend/tests/` 使用隔离 SQLite 和签发的测试 JWT 验证 HTTP 状态码、行程访问、版本操作和账号隔离。
- 通过受控的图和外部服务替身验证 SSE、恢复和 WebSocket 的身份传递，避免依赖真实模型及第三方地图。
- 运行前端构建，并在环境允许时验证浏览器登录跳转和聊天连接。检查 MCP 凭证缺失、失效和正常转发。

## 验证记录

- 后端 `python -m pytest -q -x --basetemp <隔离目录>` 通过 16 项用例，覆盖公开接口、凭证校验、行程和版本操作、规划会话隔离和 WebSocket 鉴权。测试使用隔离 SQLite，规划与外部服务使用替身。
- 前端 `npm run build` 通过，构建保留依赖包体积提示。浏览器使用临时账号验证了游客访问聊天页跳转登录、登录后返回聊天页并收到澄清回复、打开个人中心以及退出后跳回登录。澄清回复由测试替身产生。
- 用 HTTP 模拟响应验证 MCP 缺少凭证的提示、有效凭证转发和失效凭证提示。DSH 环境及真实模型、地图未联调。MCP 调用归属 `TRAVEL_API_TOKEN` 对应的账号，凭证过期需更新配置并重启 MCP 进程。
- 部署需使用环境独有的 `JWT_SECRET_KEY`。旧匿名行程仍保留，用户接口按当前账号查询。
