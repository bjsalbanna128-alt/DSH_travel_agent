# 运营身份与后台入口

任务开始日期为 2026-11-25。本文为第一项企业后台功能的实施规格。功能已实现，本地验证结果见文末。

## 原因与交付目标

目前游客和运营人员都能使用同一个账号系统，但 `users` 尚无身份字段，登录返回值只有令牌和账号信息，前端路由只判断是否登录。首期需要让多名运营人员分别用自己的账号进入同一个企业后台，同时让游客继续使用原有规划及行程入口。

交付后，验收人员可从同一登录页分别登录游客和运营账号，看到对应首页，并用真实后台接口验证身份边界。已有行程详情深链可在登录后继续打开。

## 已确认的业务边界

- 首版服务单家企业。每人使用独立账号，账号有一种身份，取值为游客 `tourist` 或运营 `operator`。所有运营账号拥有相同的后台权限。
- 本次交付共用登录、角色数据迁移、运营身份授予与撤销、后台鉴权、登录分流和可访问的后台首页。游客业务接口继续按当前用户校验资源归属，运营身份只增加后台访问权限。
- 后续独立规格负责酒店房型与每日售价、行程模板、推荐内容。价格口径已确定为运营手工维护的人民币对客售价，按房型、入住日和间夜计价。模板和推荐内容由同一运营人员编辑并直接发布。本期导航仅展示已交付的首页，后续模块完成后再挂入导航。
- 多企业隔离、后台岗位分级、在线账号管理、经营报表和待办预警属于本期范围之外。后台首页的验收以身份、导航和退出操作为准。

## 实施顺序

### 1. 给账号增加角色，并迁移旧库

在 `backend/app/db/models.py` 的 `User` 增加非空字符串字段 `role`，应用默认值与数据库默认值均为 `tourist`。写入端只接受约定的两个取值，鉴权时仅精确匹配 `operator` 才放行。

沿用 `backend/app/db/database.py` 的启动迁移方式。在 `init_db` 的事务内先执行建表，再检查旧 `users` 表是否已有该列，缺列时补列并使已有账号获得游客默认值。新库走模型建表，旧库须显式升级，单独调用 `create_all` 无法给既有表增加字段。兼容项目支持的 SQLite 和 PostgreSQL。重复启动应保留已授予的运营身份、用户 ID、密码散列和全部行程归属。先在临时旧库上验证。

### 2. 将运营授权交给部署维护者

复用公开注册或已有账号，再由具有部署环境权限的维护者在后端目录运行本地管理命令。约定命令入口为 `python -m scripts.set_user_role --username <用户名> --role operator`，撤销使用同一命令并将目标角色设为 `tourist`。每个运营账号分别授权。

命令复用应用数据库连接，按唯一用户名定位账号，在事务中更新角色，成功后输出账号、原角色和新角色。重复设置相同角色视为成功。用户不存在或角色非法时返回非零退出码，不新建账号。公开注册始终生成游客；若注册请求显式携带 `role` 字段，返回 422 并终止注册。登录身份始终以数据库角色为准。

### 3. 扩展登录接口并保护整个后台路由

| 接口 | 调用者 | 成功行为 |
|---|---|---|
| `POST /api/v1/auth/register` | 未登录用户 | 沿用原有注册字段及返回值，响应额外包含 `role: tourist`。 |
| `POST /api/v1/auth/login` | 两种身份共用 | 沿用用户名和密码，成功响应保留 `access_token`、`token_type`、`user_id`、`username`，增加数据库中的 `role`。 |
| `GET /api/v1/auth/me` | 已登录账号 | 返回当前 `user_id`、`username`、`role`，用于刷新页面和恢复升级前的会话。 |
| `GET /api/v1/admin/session` | 运营账号 | 返回当前运营账号的 `user_id`、`username`、`role`。后台首页进入时调用此接口，用于核实访问权限和显示账号。 |

在 `backend/app/api/deps.py` 复用令牌解析及按用户 ID 查库的逻辑，从同一次账号查询取得身份。保留现有 `CurrentUserId` 的字符串返回约定，以及 WebSocket 调用 `authenticate_user(token)` 的行为。增加运营鉴权依赖，并在 `backend/app/main.py` 注册的整个 `/api/v1/admin` 路由组上应用，后续后台读写接口继承该保护。

缺少令牌、令牌无效或过期、账号已不存在，均返回 401。已认证游客请求后台接口返回 403。角色从数据库读取，所以撤销角色后，原令牌的下一次后台请求即返回 403；仍在有效期内的旧版令牌可继续识别用户。角色不依赖前端缓存或请求中自报的值。各响应仅返回约定字段。

### 4. 实现登录分流和后台布局

扩展 `frontend/src/stores/auth.ts` 的用户类型及缓存，登录和注册后保存服务端返回的角色。应用从已有令牌恢复时，用 `/auth/me` 同步身份，再决定受保护页面去向；同一轮初始化共用一次请求。旧缓存缺少角色也走此流程。网络故障显示加载失败与重试，401 清理对应会话并回登录页。切换账号或退出后，前一账号的延迟响应不得覆盖新会话。

在 `frontend/src/router/index.ts` 添加 `/admin` 及运营专属路由标记，统一处理登录后的目标地址。沿用 `LoginPage.vue` 的站内已知路由校验，并补充目标角色校验。页面刷新、直接输入地址和点击菜单遵循同一规则。

| 访问情形 | 预期结果 |
|---|---|
| 正常登录，无指定目标 | 游客到 `/`，运营到 `/admin`。 |
| 未登录打开后台链接 | 转登录并记住站内目标。运营登录后回到目标，游客登录后回游客首页并提示需要运营身份。 |
| 从 DSH 打开自己的行程深链 | 登录成功后恢复完整详情地址及查询参数，详情接口继续校验归属。 |
| 已登录游客直接打开 `/admin` | 回游客首页并提示需要运营身份。直接请求后台 API 仍返回 403。 |
| 登录时目标地址无效、站外或指向登录页 | 回到该角色默认首页。 |
| 后台会话失效或运营身份被撤销 | 401 走重新登录。403 时重新读取当前身份并退出后台视图，游客仍保持登录。 |

调整 `frontend/src/App.vue` 的布局选择，为 `/admin` 使用 Vue 与 Element Plus 的独立后台布局。页面显示“企业运营后台”、当前运营用户名、首页导航及退出操作。后台会话校验通过后再展示业务区域；网络错误提供重试。退出时清理身份和会话内状态，回到登录页。游客页继续使用现有导航，登录页使用适合两种身份的提示文案。

## 验收与测试计划

后端功能用例放入 `backend/tests/test_operator_access.py`，沿用现有临时数据库和 FastAPI 测试客户端。以下均为交付时必须核对的行为。

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| AC-1 | 新库、旧库和重复迁移 | 新注册默认游客；旧账号可用原密码登录并读取自己的历史行程；二次迁移保留已经授权的角色。 |
| AC-2 | 注册、授权和撤销 | 注册自报角色返回 422；用管理命令分别授权两名运营，两人均能登录后台；撤销其中一人只影响该账号。重复执行和不存在账号的结果符合命令约定。 |
| AC-3 | 服务器权限 | 同一后台接口分别用无令牌、过期令牌、游客令牌和运营令牌请求，依次得到 401、401、403、200。被撤销者使用原有效令牌得到 403；前端修改本地角色无法获得后台数据。 |
| AC-4 | 双端分流与深链 | 真实浏览器使用两种账号登录，核对默认首页、直接进入后台、DSH 行程深链和非法跳转目标。运营和游客仍只能读取自己名下的游客行程。 |
| AC-5 | 刷新、退出和切换账号 | 刷新后台能恢复正确账号；旧缓存只有用户 ID 和用户名时可恢复身份；退出后通过后退或直接打开后台链接需要登录；同一浏览器切换账号时不残留上一人的后台内容。 |
| AC-6 | 失败恢复与现有入口回归 | 断网恢复时可重试；401 与 403 展示和跳转有区别。现有注册、游客登录、草稿确认、HTTP 和 WebSocket 身份校验回归通过。 |

交付者在 `backend/` 运行 `python -m pytest`，在 `frontend/` 运行 `npm run build`，并按 AC-4 至 AC-6 在浏览器走查。迁移记录注明实际验证的数据库类型。回填命令、结果和未验证项后，以本规格、实现和测试作为同一项功能交付。

## 验证记录

- 在 `backend/` 使用隔离配置执行 `python -m pytest -q`，62 项通过，含本次 4 项运营身份测试。覆盖 AC-1 至 AC-3，包括旧库迁移与二次启动、旧账号密码和行程归属、注册拒绝自报角色、两名运营分别授权、原令牌撤销后返回 403，以及 HTTP、WebSocket 和草稿确认回归。
- 在 `frontend/` 执行 `npm run build` 成功。构建报告了大于 500 kB 的包体积提示。
- 在真实浏览器用隔离服务和测试账号完成 AC-4 至 AC-6 的走查。验证游客与运营默认首页、拒绝游客打开后台、登录后保留 DSH 形态的行程深链及查询参数、非法登录目标回退、刷新和旧缓存恢复、退出后后退与直达均需登录，以及后台会话请求延迟时退出并切换运营账号。
- 在同一浏览器验证伪造缓存角色后直接请求后台仍返回 403。身份恢复请求中断及后台服务返回 503 后均可重试。后台返回 401 时重新登录，撤销运营角色触发 403 时重新读取身份并保留游客会话。
- 实测数据库为 SQLite，包括临时文件旧库、新库和浏览器验收用的内存库。PostgreSQL 迁移路径已实现，本机无可用的 PostgreSQL 实例，尚未实测。DSH 测试使用同形态的本地深链，实际 DSH 服务尚未联调。
