# AI 运营 · 首页推荐投放

2026-11-26 ｜ 功能迭代 ｜ 已实现

## 目标与范围

运营已能在“推荐内容”制作、排序、发布和下架推荐卡。本次增加“AI 运营 → 首页弹窗投放”，让运营选择已发布内容、设置起止时间、临时停投并预览某时刻的轮播顺序。唯一投放位置是游客首页弹窗。沿用已发布卡片、现有展示顺序以及“每次登录会话最多一次”的约定。本期不采集用户画像或点击数据。

例：把一张赏花卡设为北京时间 3 月 1 日 00:00 开始、4 月 1 日 00:00 结束，便能完整覆盖三月。3 月 31 日仍可出现在新拉取的轮播列表中，4 月 1 日零点起退出列表；内容库里的已发布卡片仍可供下次使用。

## 页面与运营动作

| 动作 | 结果 |
| --- | --- |
| 选择内容并启用 | 从已发布内容中选卡，设置开始、结束时间并保存后直接生效。两端均可留空，分别表示立即开始和长期有效。已有投放记录时直接编辑同一条。 |
| 查看投放 | 列表显示标题、当前发布版排序值、起止时间、有效状态及操作人。状态按“内容已下架 → 已停投 → 未开始 → 已结束 → 投放中”判定。可区分主动停投与自然到期。 |
| 临时停投或恢复 | 停投立即排除后续读取；恢复后仍要满足内容发布状态和时间窗口。结束时间已过时提示先调整日期。 |
| 预览 | 可选北京时间，默认现在；展示按该时刻筛出的卡片及顺序。与游客接口使用同一筛选排序函数，按当前已发布的内容快照预览。不影响游客弹窗次数。 |

排序始终取当前发布版本的 `display_order` 升序，再按内容 ID 升序。编辑内容草稿不会改变线上卡片和顺序。页面提供返回“推荐内容”调整顺序的入口。已经打开的弹窗按打开时取得的卡片播放，后续游客请求读取最新投放结果。

## 开发落点与存量兼容

1. 新增投放记录，以推荐内容 ID 唯一关联主记录，不复制标题、封面和顺序。保存启用状态、可空起止时刻、修订号、操作人和更新时间。界面明确标注北京时间；API 接受带时区的时刻并统一为 UTC，资格为“启用，且开始 ≤ 当前时刻 < 结束”。双端给定时必须开始早于结束。
2. 升级时为**当时已发布的内容**一次性补建“启用、无时间限制”的记录，保留原首页效果。升级完成后，首次发布的新内容默认待选择，明确投放后才展示；历史草稿首次发布也按新规则。已有投放记录的内容下架立即失去资格，同一内容重新发布时沿用原投放窗口及启停状态。后台明确展示这条规则。迁移可重跑，不恢复手动停投，不重复补建，不把升级后新内容误当成存量。
3. 运营路由下增加投放列表、可选已发布内容、保存或停投、指定时刻预览接口，使用现有运营鉴权。保存采用预期修订号，冲突返回 409；非法时间或首次选用未发布内容返回 422。时间生效依据每次查询的服务端时钟，无需定时任务切状态。
4. 游客读取时，在 `services/recommendations.py` 的已发布快照查询中加入投放资格。保持游客列表字段、封面读取权限、排序和分页形态兼容。投放策略作用于首页卡片列表；运营内容管理和已发布快照的生命周期照旧。全无符合项时返回空数组，沿用 `HomeRecommendations.vue` 既有无卡不弹逻辑。

## 验收与回归

| 场景 | 通过条件 |
| --- | --- |
| 升级 | 原先可见的两张卡升级后以同一顺序展示；停投一张后重启、重复初始化，仍只展示另一张。新内容只发布未投放时仍可在后台选中，游客列表不出现。 |
| 时间边界 | 固定服务端时钟验证开始前、恰好开始、结束前、恰好结束，以及单端或双端留空；同一时刻的运营预览与游客列表 ID 和顺序一致。 |
| 内容与投放联动 | 已投放卡只编辑草稿时仍显示原发布版，新版本发布后切换封面与顺序。内容下架、手动停投或到期分别生效；恢复与重新发布不会越过窗口。 |
| 游客体验与权限 | 同一登录会话关闭弹窗后刷新、临时新增投放均不会再次弹出；新会话获得当前名单。无卡时能直接开始规划。验证无权访问运营接口、同修订并发写仅一方成功。 |

在 `backend/tests/` 增加固定时钟、升级、接口契约与并发用例，回归已有发布和封面测试；前端执行 `npm run build`，实测后台设置及游客首页轮播。重点副作用为升级后首页意外清空、边界时间差一天、发布与投放状态混淆，以上场景均须通过。

**实现与验证记录**　升级事务一次性保留存量已发布卡片。游客首页与后台预览使用同一筛选排序，时间按北京时间输入、按 UTC 存储。自动化测试覆盖重复初始化、开始和结束边界、停投、下架、封面及并发保存。前端构建通过，本地浏览器验证了选择已发布内容、保存、预览封面和游客首页展示，关闭弹窗后同一会话刷新不再展示。
