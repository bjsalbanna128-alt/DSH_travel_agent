# 收敛聊天入口：保留首页，移除独立聊天页

## 原因与目标

C 端目前有两个聊天面：首页（`/`）内嵌的聊天框，和独立聊天页（`/chat`）。两者功能重叠：

| | 首页 | `/chat` |
|---|---|---|
| 通信通道 | 澄清走 HTTP，规划走 SSE | 全程 WebSocket |
| 规划进度 | 跳转 `/plan` 查看 | 原地实时显示 Agent 进度 |
| 审批与调整 | 跳转 `/trip/:id` 的确认面板 | 原地弹审批卡片 |
| 示例引导 | 有 4 个示例标签 | 只有一行提示 |

首页本身就能聊天，页面上方还挂着一个「聊天规划 (WebSocket)」按钮通向另一个聊天页，入口重复；两套聊天 UI 共约 900 行，需要同步维护。模板入口也因此在两个页面各放了一份。

目标：只保留首页一个聊天面，删掉独立聊天页及其入口，减少重复实现。

## 范围和边界

### 一、移除

- 路由 `/chat` 的**页面记录**（`name: 'chat'` 与组件引用；保留一条 `redirect: '/'` 的兼容记录，见下）。
- `views/ChatPage.vue`（整页删除，含其上新增的模板入口）。
- 首页「聊天规划 (WebSocket)」按钮。

### 二、调整

- `views/InspirationPage.vue` 里的「← 返回聊天」「回到聊天自己规划」两个按钮改为回到首页 `/`（原指向 `/chat`）。
- 旧地址兼容：`/chat` 被直接访问时重定向到 `/`，不出现空白页；路由中保留一条重定向记录，不保留页面组件。

### 三、保留

- 后端 `/ws/chat/{thread_id}` 端点与其测试本次不动，前端不再调用。
- 首页的澄清、规划、确认流程不变。
- 首页的模板入口保留；模板入口最终只存在首页一处。

### 非目标

- 不删除后端 WebSocket 端点（单独迭代评估）。
- 不把 `/chat` 的"原地实时 Agent 进度"迁移到首页（`/plan` 页已有等价的进度展示）。
- 不改造首页布局（除删掉那个按钮）。
- 不调整审批与调整流程的现有位置（仍在 `/trip/:id`）。

### 可能受影响的现有行为

- 首页少一个按钮，主操作变为下方的输入框，页面更聚焦。
- 前端只剩 SSE 一条规划链路，WebSocket 仅后端保留、无 UI 调用。
- 访问旧地址 `/chat` 会跳到首页，书签与历史记录不会 404。
- 模板入口从两处收敛到一处。

## 验收

1. 首页不再出现「聊天规划 (WebSocket)」按钮。
2. 访问 `/chat` 自动跳转到 `/`，不出现空白页或 404。
3. 首页完整流程可用：输入需求 → 澄清 → 开始规划 → `/plan` 看进度 → `/trip/:id` 确认。
4. 首页输入框上方的「没有想法？试试随机旅行」入口仍可用，`/inspiration` 的返回按钮回到 `/`。
5. 全仓检索无 `/chat` 页面组件引用；`npm run build` 通过。
6. 后端 `/ws/chat/{thread_id}` 仍可正常连接（仅回归，不影响前端）。
