# 推荐内容管理与发布

任务日期为 2026-11-25，状态为已实现。对应企业后台“行程与内容 → 推荐内容”，交付范围包括游客首页弹窗。

## 目标与验收主线

运营为两个景点各制作一张推荐卡，预览并直接发布。游客登录后进入首页，看到一个可关闭的弹窗，两张卡按运营设置的顺序轮播。游客关闭、刷新、离开再返回，本次登录都不会再次弹出。运营把第一张卡下架后，新登录的游客只看到第二张。

沿用单企业、多个同权运营账号。卡片采用一张封面图和一段纯文本短文。运营可维护其他运营创建的卡片。首版覆盖内容编辑、上传、预览、排序、发布、下架和首页展示。文章详情、富文本、自定义跳转链接、定向投放、统计和定时投放属于后续需求。

## 一、卡片内容与后台操作

| 字段 | 首版约定 |
|---|---|
| 推荐标题 | 新建草稿必填，去除首尾空白后为 1–40 个字符。示例为“秋天去九寨沟看彩林”。 |
| 推荐地点 | 目的地或景点的展示名称，发布必填，最多 100 个字符。填写名称即可，可推荐尚未录入商品库的地点。 |
| 推荐短文 | 发布必填，最多 200 个字符，按纯文本展示。手机上较长的内容可在卡内滚动阅读，关闭按钮始终可见。 |
| 封面 | 发布时恰好一张有效图片。建议按 16:9 取景，后台预览与首页采用同一裁切规则；图片替代文字使用地点和标题。 |
| 展示顺序 | 非负整数，默认 100，数值小的在前。数值相同按稳定的内容 ID 升序。排序取当前发布版的值。 |

在现有 `AdminLayout.vue` 的“行程与内容”下增加“推荐内容”。列表可按草稿标题、地点和发布状态筛选，显示封面缩略图、草稿标题、线上版号、排序及“有未发布修改”提示。操作包括新建、编辑、预览、发布和下架。

编辑页先保存标题创建草稿，再上传或替换封面。表单同时展示桌面和手机效果；预览复用游客卡片组件，标明“草稿预览”。有未保存修改时离开应提示；点发布时先保存表单，保存或图片上传失败时保留当前输入，允许重试。下架操作展示内容标题并要求确认。

## 二、草稿、发布和封面

沿用③行程模板已经实现的草稿修订号、快照和权限处理方式。推荐卡使用独立数据模型和接口。

| 操作 | 对已发布推荐的影响 |
|---|---|
| 首次保存草稿 | 仅运营可见；标题之外的字段允许暂缺。 |
| 首次发布 | 校验地点、短文、封面及顺序，通过后一次性发布 v1。 |
| 修改文字、换图或调整顺序 | 保存草稿期间，线上文字、封面和顺序仍取上次发布快照。 |
| 再次发布 | 同一事务生成下一版并切换线上快照；失败时旧版继续可读。已上线且内容未变时不额外生成版本。 |
| 下架与重新发布 | 下架后从后续读者查询中移除。草稿和历史快照继续保留；再次发布时重新校验并递增版本。已打开的弹窗按本次取得的列表展示，下一次读取取最新结果。 |

**表结构建议。** 主表 `recommendations` 保存稳定 ID、草稿字段与封面 ID、线上状态、最新版本、编辑修订号、操作人和时间；`recommendation_versions` 保存唯一的“内容 ID + 版本号”及完整发布快照（含封面 ID、排序）；`recommendation_images` 保存不可变图片 ID、校验后的图片字节、真实 MIME、尺寸和大小。首版采用数据库存图，使 SQLite 和 PostgreSQL 共享一套持久化与备份路径。列表响应只返回图片资源地址及元数据，按需单独取图。

**上传规则。** 只接收 JPEG、PNG、WebP 静态图片，单文件最大 5 MiB，解码尺寸最大 1600 万像素。按实际字节校验格式、尺寸及是否可解码，拒绝损坏文件和动画，服务端为图片生成 ID。沿用仓库依赖约定，若选用图片解码库，列入后端依赖及镜像安装步骤。上传端点限制请求体，并对齐 `nginx.conf` 的代理体积限制。更换封面时，在同一事务写入新图并更新草稿引用；失败时维持原图。历史快照引用过的图片须保留，无草稿或快照引用的旧图可清理。相同 ID 始终对应相同字节。

**并发规则。** 保存、换图、发布、下架均使用 `expected_revision` 校验并返回新修订号。两个运营同时修改时，旧修订号返回 409，保留编辑者输入；连续点击发布或超时重试不会产生两份发布版。首次部署新增表，沿用已有初始化流程；升级和重复启动均应保留既有模板、资源及账号。

## 三、HTTP 接口与可见性

以下路径相对于 `/api/v1`。运营路由统一挂到已有的后台鉴权组。游客请求复用现有 Bearer 登录，图片通过带身份的请求读取为 Blob 后展示，切换或卸载时释放对象 URL。

| 接口 | 契约 |
|---|---|
| `GET /admin/recommendations`、`POST /admin/recommendations` | 分页查询管理列表，或创建草稿。 |
| `GET /admin/recommendations/{id}`、`PUT /admin/recommendations/{id}/draft` | 获取或保存草稿字段；返回修订号和发布状态。 |
| `PUT /admin/recommendations/{id}/draft/cover` | 上传原始图片字节，查询参数携带预期修订号；校验成功后绑定到该草稿。 |
| `GET /admin/recommendations/{id}/draft/cover` | 供运营预览当前草稿封面。 |
| `POST /admin/recommendations/{id}/publish`、`POST /admin/recommendations/{id}/unpublish` | 发布及下架。发布响应包含实际生效的版号与修订号。 |
| `GET /recommendations` | 已登录账号可读，返回所有当前已发布卡片，按已发布顺序排列。每条只含 ID、版本、标题、地点、短文及该版本的封面地址；无内容返回空数组。 |
| `GET /recommendations/{id}/versions/{version}/cover` | 校验该内容仍上线且版号为当前线上版本，再返回对应图片。草稿、下架及过时版号返回 404。 |

未登录返回 401，游客访问后台接口返回 403，记录不可见或不存在返回 404，修订冲突返回 409。上传超限返回 413，文件格式不支持返回 415，内容损坏或发布资料不全返回 422。读者列表与封面响应避免保留可跨会话复用的陈旧缓存。草稿图片、员工信息和历史发布记录仅在授权范围内读取。

## 四、游客首页弹窗

**触发位置。** 在 `HomePage.vue` 登入后的游客首页加载推荐。游客身份和当前路由均已确定后再触发。运营后台、登录页、规划页及从 DSH 打开的行程详情均不触发；从详情主动返回首页时再判断。推荐异步加载，首页需求输入框、规划按钮可立即使用。若游客已经开始输入、离开首页或切换账号，迟到的响应不得打断当前操作。

**会话口径。** “每次会话”按同一浏览器、同一账号的一次成功登录计，注册后自动登录同样开启一次会话。刷新、返回首页和打开同源新标签页都沿用同一会话；退出后重新登录，同一账号也获得一次新展示机会。新发布内容不会重置已经使用的展示机会。

- 在现有 Pinia 认证流程里为成功登录生成独立的随机会话标识，与当前账号一同持久化；单纯调用 `/auth/me` 或刷新页面沿用原标识。升级前已有有效登录且缺标识时，为现有会话补一次。不要把明文令牌作为展示标识。当前的内存 `sessionVersion` 可用于丢弃过期响应，刷新后的频控另行持久化。
- 以“账号 ID + 登录会话标识”记录是否已展示。至少一张卡的封面已可显示、当前仍在合适的游客首页时，才在实际打开弹窗前领取本次展示机会。用同源跨标签页的原子操作避免重复，例如 IndexedDB 唯一键事务；两个标签页同时进入最多一个成功。若无法可靠记录，则本次不弹。退出并切换账号后，旧请求和定时器失效。
- 请求失败、列表为空、全部封面无法显示或加载完成前离开，均不消耗机会。本次停留不循环重试，下次主动进入首页可重新判断。图片加载失败的卡片跳过，有可展示的下一张时继续；若全部失效则收起弹窗。
- 一张卡只展示静态内容；多张卡在**同一个弹窗**内按顺序循环，默认每 5 秒切换，可用上一张、下一张和位置指示器。游客手动切换后暂停自动轮播。鼠标悬停、键盘焦点在卡片上或页面切到后台时暂停计时；系统开启减少动态效果时默认手动浏览。
- 随时可以点关闭或按 Escape 退出；关闭后焦点返回首页，清除定时器。弹窗首次出现即计为已展示，即使游客直接刷新或离开，也不再重复打开。

## 五、验收与测试

| 场景 | 通过条件 |
|---|---|
| 制作与预览 | 标题可建草稿；缺地点、短文或封面时发布失败并标出字段。上传一张有效图片后可预览手机和桌面效果。游客无法读取草稿文字及草稿封面。 |
| 换图与发布 | v1 发布后保存新短文、封面和顺序，读者仍能看到完整 v1；发布 v2 后三项同时切换。图片上传失败保留原草稿封面；发布失败保留旧线上版。 |
| 排序、下架与并发 | 两条推荐按发布排序，顺序相同时结果稳定。下架一条后重新读取只剩一条，旧封面地址不再可取。两名运营使用同一修订号时只能有一个写入成功。 |
| 首页 0、1、多条 | 无内容时首页直接可用；一张卡不启动轮播；两张以上约 5 秒切换、可手动切换与关闭。手机上能读完正文并找到关闭按钮。 |
| 会话频控 | 同次登录关闭、刷新、返回首页均不再弹；不点击关闭直接刷新也不再弹。两个同源标签页同时进入仅弹一次。重新登录或换账号后可重新展示。 |
| 深链与异常 | 从 DSH 直接进入路书不弹；尚未展示时从路书去首页可弹。断网、加载慢、个别或全部图片损坏时规划仍可用。离开首页或退出后无延迟弹窗。 |
| 权限和存储 | 检查 401、403、上传边界、非法图片及速点发布。服务重启后线上封面仍可读取，重复初始化不丢既有数据。 |

后端在 `backend/tests/` 增加推荐内容回归用例，使用隔离数据库和小型测试图片。前端覆盖排序、轮播计时、跨标签页领取及账号切换；在真实浏览器走查后台发布、游客正常登录、刷新和 DSH 深链。交付者运行后端全量 pytest、前端构建，并在带反向代理的环境验证允许大小的封面能上传和读取。

## 验证记录

### 实现和影响

- 企业后台可管理推荐草稿、上传封面、查看桌面与手机预览、发布和下架。标题、地点和短文仍可自由填写，发布时校验资料完整性。修改文字、封面和顺序存入草稿，发布时一起切换线上版本。
- 封面通过 Pillow 验证真实格式与像素，依赖已声明在后端和镜像安装步骤。图片随数据库备份。发布快照引用过的图片继续保留，因此更换并发布封面会增加数据库的备份体积。
- 登录成功生成与账号绑定的随机会话标识。IndexedDB 记录展示机会，跨标签页共用。浏览器无法写入展示记录时跳过弹窗，首页规划入口继续可用。
- 点击发布会保存有改动的表单，并上传已选文件后再发布。遇到上传或修订冲突时保留当前输入。展示顺序采用数据库兼容的非负整数范围，最大值为 2,147,483,647。
