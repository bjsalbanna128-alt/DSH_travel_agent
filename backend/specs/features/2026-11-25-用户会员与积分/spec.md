# 用户会员：会员档案、常用出行人与订单积分

任务日期为 2026-11-25，状态为已实现。对应企业后台“用户会员”与游客端个人中心。沿用单企业、多个同权运营账号。

## 一、交付结果与边界

运营打开会员列表即可找到每一个游客账号，包括从未打开会员中心的老游客。运营可查会员档案、脱敏的出行人资料、只读旅行偏好，以及积分余额和来源订单流水。游客能维护本人及常用出行人的资料，查看自己的积分、到期情况和变动原因。

积分唯一获得来源为订单支付成功。实付人民币 1 元得 10 分，退款成功按该订单剩余实付重新计算。每笔订单积分有效期 12 个月。本期积分仅用于记账和展示；人工加扣、手动改余额、赠分、成长值、会员等级、权益倍率、积分使用和抵扣试算均排除在本期交付之外。

当前仓库尚无订单、支付和退款模块。本期实现可测试的订单积分内部服务，使用模拟的成功支付和退款事件验收。未来由订单服务在核实支付或退款成功后接入。实际接入前，无有效订单事件的账号显示 0 分。页面、公开 HTTP 接口、运营接口和行程确认流程均不提供积分写入入口。

## 二、游客名单与档案

| 使用方 | 页面和操作 |
|---|---|
| B 端会员列表 | 在后台导航增加“用户会员”。从角色为 `tourist` 的账号出发，按用户名、注册时间筛选并分页，展示资料是否完善及有效积分。左关联档案及积分汇总。无档案、无积分的游客也返回；运营账号排除在名单之外。 |
| B 端会员详情 | 只读展示账号、脱敏的姓名、手机号和证件号、出行人关系，以及已有 AI 偏好和积分流水。可按订单、变动类型和时间查账。档案和偏好分别标记来源。 |
| C 端会员中心 | 游客可编辑本人昵称、头像、生日、性别、姓名、电话和可选证件，管理常用出行人。展示有效积分、未来 30 天内到期的批次与最近流水，可分页查询全部流水。无记录时显示 0 分和对应空态。 |

账号注册即进入会员名单，资料首次填写时才创建档案。证件齐全时显示“证件已填写”，未填时显示“未填写”。采集证件只代表用户提供了资料，本期不产生身份核验结论。会员资料由游客显式修改；AI 自动维护的 `user_profiles` 独立保存，缺失时展示空态。档案写入使用允许字段清单，角色、积分、归属账号及证件状态均由服务端决定。

### 证件与出行人

- 本人与常用出行人都可以只填非证件资料。录入证件时，证件类型与号码必须成对提供，支持身份证、护照、港澳证件、台湾证件及其他证件。出行人另存姓名、可选联系方式、关系和默认标志。游客只维护自己名下的记录。
- 读取本人或自己管理的出行人时可显示姓名；电话和证件号均返回掩码。运营详情对姓名、电话和证件号全部脱敏。账号公开昵称与真实姓名分字段、分用途返回。编辑页面把掩码作为提示；未修改证件字段则保留原值，明确清除才删除密文与查重摘要，传入掩码作新号码应拒绝。
- 同一账号的出行人以“证件类型＋规范化号码”去重，仅对有证件的记录建立唯一约束；不同家庭账号可分别维护同一位出行人。允许一个账号有多名无证件出行人。每个账号至多一名默认出行人，更换默认在同一事务完成；删除最后一名后允许列表为空。
- 证件号以 AES-256-GCM 加密保存，每次写入使用新的随机 96 位 nonce，密文携带密钥版本、nonce 与认证标签。查重使用 HMAC-SHA256，输入包括证件类型和规范化号码。沿用 `pii_encryption_key` 配置，以 HKDF-SHA256 为加密与查重派生不同子密钥。手机号同样加密保存，读接口返回掩码。证件或电话的掩码可在写入时另存，供列表读取。对短值全部遮盖，姓名避免因过短而对运营完整展示。
- 管理端及游客端均无读取完整证件号的接口。输入校验错误、请求日志、异常详情和前端持久缓存不得包含原始证件号或手机号。密钥缺失或不足 32 字节时，涉及加密的新写入返回 503，其余非敏感档案、积分、登录和查询仍可用。部署由环境提供密钥，验证使用合成证件数据。

## 三、订单积分规则

### 金额和计算

内部契约使用人民币整数分。订单应得积分为“剩余实付分数整除 10”，只在订单层面向下取整。支付成功时按订单的实际到账金额入账；创建订单、未支付、支付失败、确认行程均不入账。跨订单各自取整，支付时本轮约定每个订单对应一笔最终成功实付金额。

退款只处理已成功且属于原订单的退款，以独立退款单号区分多次部分退款。剩余实付等于原订单实付减去累计成功退款；重新计算应得积分，按新旧应得的差额冲回原批次。冲回上限为该批次仍有效的剩余分数，不动用其他订单的积分。全额退款后原订单应得积分为 0。累计退款不得超过原实付。

| 操作 | 原订单剩余实付 | 本次积分余额变化 | 结果 |
|---|---:|---:|---|
| 支付成功 99.99 元 | 99.99 元 | +999 | 原订单产生独立批次 |
| 首次退款成功 20 元 | 79.99 元 | −200 | 该批次剩 799 分 |
| 再退 0.01 元 | 79.98 元 | 0 | 仍应得 799 分，保留退款处理记录 |
| 有效期内退清剩余 79.98 元 | 0 元 | −799 | 原批次归零 |
| 另一场景：批次已全部过期后发生退款 | 按退款金额更新 | 0 | 记录退款事实，不再次扣余额 |

### 到期与有效余额

每批积分按原订单支付成功时间起算 12 个自然月，以北京时间计算周年时刻并以带时区时间持久化；下年无对应日期时取该月最后一天的同时刻。重复投递、迟到事件及部分退款都不延长有效期。当前时间达到 `expires_at` 即过期。

游客和运营看到的**有效余额**统一按未到期批次剩余积分之和计算。一次取同一查询时刻计算余额和即将到期明细。定时任务每天扫描到期批次，只对该批剩余积分生成一次负向过期流水并清零；启动后可补扫，重复、并发运行不能重复冲减。数据库中的账面余额在过期流水补记之前可能与有效余额不同，接口必须返回有效余额。实现者需提供可独立运行的清理入口，并明确实际定时调度方式。

退款与过期任务并发时，按订单批次串行更新。处理已过期批次的退款前先结清该批剩余过期金额，再记录对有效余额为零的退款。其他未过期批次须原值保留。迟到支付事件若入账时已超有效期，留存支付和过期记录，查询不会临时显示可用积分。

## 四、数据、接口与一致性

| 建议表 | 用途 |
|---|---|
| `member_profiles`、`travelers` | 会员档案以游客账号 ID 为主键，出行人以独立 ID 和所属游客 ID 建立归属。保存必要资料、敏感字段密文、掩码和查重摘要。 |
| `point_accounts` | 每位游客一个账户，保存已记账的积分汇总。可在首笔订单事件时幂等建立；展示有效余额时按到期规则计算。 |
| `point_lots` | 每个订单一个批次，按来源订单唯一，保存账号、原实付金额、累计退款金额、当前应得积分、剩余积分、支付成功时间与到期时刻。 |
| `point_transactions` | 追加写入的流水，记录类型（支付入账、退款冲回、过期）、带符号的变动积分、关联订单／退款单、来源事件键、金额、业务时间及记账后余额。本次变动为零的退款也应可追踪。 |

- 同一事务更新批次、账户和流水。按来源事件键建立数据库唯一约束；同一成功支付或退款重复投递只生效一次。重复键对应不同会员、订单或金额视为冲突；并发的两笔不同退款不得相互覆盖。退款早于原支付事件时返回可重试的“原支付尚未入账”，不预扣、不消耗成功幂等键。
- 内部支付服务接收可信订单号、所属游客、实付金额、支付成功时间与支付事件 ID；退款服务接收原订单号、独立退款单号、成功退款金额及时间，从原订单确定归属。测试直接调用内部服务。订单迭代负责事件真实性、可靠投递及重试。
- C 端以 `/api/v1/members` 为前缀，提供本人档案 GET/PATCH、出行人列表与增改删、积分概览、积分流水分页。B 端以 `/api/v1/admin/members` 提供游客列表、只读详情和积分流水。后台沿用 `require_operator`，C 端校验游客身份与记录归属。无登录返回 401，角色不符返回 403，跨账号访问个人记录返回 404。响应中不暴露密文、查重值或密钥信息。
- 新库及旧库均按项目现有方式初始化新增表，可重复执行。已有游客和历史行程不会自动产生积分。普通偏好读写、规划确认、既有消息管理相互独立。

## 五、验收与回归

| 场景 | 通过条件 |
|---|---|
| 游客名单与只读运营权限 | 未建档的老游客出现在后台，默认 0 分，运营账号不出现在名单中。运营能查流水，不能调整积分或代改游客档案；游客修改资料也无法写入余额。 |
| 可选证件与归属 | 无证件可使用会员中心。本人和出行人可填写、替换或清除证件；运营只见脱敏数据。修改昵称后原证件仍可识别。跨账号读取、更新或删除出行人均失败。 |
| 敏感信息与查重 | 用合成数据验证随机加密可解密、同账号同类型证件去重、跨账号允许、多个空证件可保存；无密钥仅阻断需加密的写入。检查 API 错误体和日志无原始证件号、电话。 |
| 唯一积分来源 | 注册、补档、行程确认均为 0 分。模拟支付 99.99 元只入账 999 分，支付失败无流水。两个订单分别低于 0.10 元时均为 0 分。 |
| 退款与重试 | 验证上表的多次部分退款、全额退款、金额过大、先退款后到账、重复及并发投递。退款记录可按原订单和各退款单号对账。 |
| 批次独立及有效期 | 同一会员有已到期 300 分和未到期 500 分，定时任务未跑时两端已显示 500；任务补跑两次只产生一次 −300 流水。已过期订单再退款，其余 500 分不受影响。覆盖闰日和到期时刻边界。 |
| 对账与失败回滚 | 任一已提交事务后，带符号流水之和等于账面余额；有效余额等于未到期批次剩余之和。模拟写入中断，账户、批次、流水均无半笔变更。 |
| 页面与回归 | 在独立游客及运营会话验证页面、权限、空态、脱敏、余额和到期提示一致。后端在隔离库运行全量 pytest，前端运行构建；回归登录、原个人偏好和行程确认。 |
