# AI 运营 · 对话配置

2026-11-26 ｜ 功能迭代 ｜ 已实现

## 目标与范围

运营能决定游客发来需求后，系统怎样回复、还要问什么、何时可以开始规划。在后台用草稿试聊，满意后由同一运营直接发布。验收以游客实际收到的回复和最终进入规划的参数为准。游客打开首页、尚未发消息时的 Vue 欢迎语留待后续。该功能仅作用于经过澄清的入口，不给直接调用规划的客户端额外增加对话步骤。

现有 HTTP 澄清接口与 WebSocket 的 chat 消息都调用 `graph/nodes/clarify.py`。模型负责抽取需求，但节点随后自行根据目的地和天数决定 `ask/ready` 并生成回复。因此要把配置接到后端的判断与回复生成处。沿用现有 `action/message/travel_request/missing_fields/turn/thread_id` 契约。

## 运营页面与规则

“AI 运营 → 对话配置”展示当前发布版本、编辑草稿、保存、模拟试聊、发布。试聊区展示游客实际会收到的文字，并单独列出目前已收集字段、下一个缺项和是否就绪。试聊可清空重来，无需生成真实行程。

| 配置 | 首版规则 |
| --- | --- |
| 首句回复 | 一段可留空的纯文本引导语。游客首次发消息后，与本轮追问或就绪提示合在一条回复中；同一会话后续轮次不再追加。首次已提供完整需求时也能直接就绪。 |
| 必问项和顺序 | 目的地、天数始终必问；预算和节奏可各自设为必问或选填。运营可以调整追问顺序。每次只问优先级最高的一个缺项；已回答的字段跳过，接受游客更正。同行人、偏好等原有信息继续正常提取。 |
| 追问文案 | 四个字段分别设置非空纯文本问题，例如“这次旅行总预算大约是多少元？”。配置只控制展示文案，不接受脚本、系统提示词、模型参数或任意变量表达式。 |
| 默认值 | 选填预算支持“不限”或正数人民币，选填节奏支持轻松、适中、紧凑。仅在就绪时补缺；必问字段禁用默认值。游客明确说“预算不限”视为已答，沿用原有不限预算表示。 |

初始发布版复现原行为，首句引导为空，仅目的地、天数必问，选填预算不限、节奏适中。配置不允许删除固定必问项、重复排序字段、非法枚举或负预算。保存时校验字段类型，发布时再次校验完整性；页面明确指出需修改的字段。

## 开发落点

1. 后端保留一份企业共享草稿、不可变发布版本和当前发布版本指针。记录版本、修订号、操作人和时间。保存与发布携带预期修订号，过期返回 409；发布快照和切换当前指针在同一事务完成。初始配置可重复初始化，重启不覆盖运营改动。
2. 首轮请求按已认证账号和 `thread_id` 唯一绑定发布版本，在服务端保存必要的已答字段与轮次。后续 HTTP/WS 澄清读取同一绑定；两个用户同名线程相互独立。首轮缺少线程 ID 时沿用现有生成与返回逻辑。并发首轮只产生一份绑定。升级前已有历史的会话第一次续聊时绑定兼容初始版，导入已有明确答案，避免中途增加追问。原地重复提交相同轮次不得重复推进。
3. 模型抽取只合并游客表达过的信息与明确更正，将“已回答”与最终默认值分开记录，特别处理模型输出的示例值、零值和空数组。按绑定版本在服务端依次生成缺项、决定动作、渲染回复，再将预算和节奏交给已有规划入参转换。试聊和真实入口复用这段逻辑。
4. 在受运营鉴权保护的 `/api/v1/admin/ai/dialog-config` 下提供读取、保存草稿、发布和试聊操作。试聊固定本次选用的草稿修订，与游客会话隔离；草稿改动后可重新试聊。匿名 401、游客 403。模型调用失败沿用可重试错误，失败轮次不写为已答或就绪。

## 验收与回归

| 场景 | 通过条件 |
| --- | --- |
| 试聊与发布 | 草稿把预算设为必问，并编辑首句。输入“成都三天”，试聊显示首句和预算问题；草稿发布前，新游客仍按原规则就绪。发布后新游客得到与试聊一致的追问。 |
| 首轮完整与多轮更正 | “去成都三天，总预算两千”直接就绪，预算 2000；首轮缺预算、次轮答“两千”时保留成都三天，首句只出现一次。答“预算不限”也可结束追问。 |
| 默认值与会话版本 | 把选填节奏默认设为轻松，明确说“紧凑”的游客仍按紧凑规划。旧会话进行中发布新版，旧会话保持原版本，新会话使用新版；重启、切换账号及两入口都符合隔离规则。 |
| 权限、并发与降级 | 验证 401/403、非法配置、两个运营同时发布、试聊失败后重试。失败和冲突不影响线上版本。试聊不会产生正式草稿、通知或工单。 |

在 `backend/tests/` 增加模拟模型抽取的服务及 HTTP/WS 用例，覆盖游客澄清到规划参数的交接。前端执行 `npm run build`，实测后台试聊、发布和现有游客对话。潜在副作用为默认值误算成已回答、同一会话切换规则和重复追问，分别由上述用例回归。

**实现与验证记录**　后台支持保存、试聊和发布。HTTP 与 WebSocket 共用账号与线程绑定，服务端按会话固定发布版本并重放已经成功的同一轮。模型只提取新答案，追问、就绪和默认值由后端处理。自动化测试覆盖隔离、版本切换、发布冲突、失败重试及两个入口接续。前端构建通过，本地浏览器使用模拟模型验证了试聊、发布和游客输入“两千”后就绪并进入规划。
